xterm.js is distributed exclusively through npm as [`@xterm/xterm`](https://www.npmjs.com/package/@xterm/xterm). The current stable version is **6.0.0**.

## Package managers

<CodeGroup>

```bash npm
npm install @xterm/xterm
```

```bash yarn
yarn add @xterm/xterm
```

```bash pnpm
pnpm add @xterm/xterm
```

</CodeGroup>

## Importing the Terminal class

<Tabs>
  <Tab title="ESM">
    The recommended approach for modern bundlers and TypeScript projects:

    ```typescript
    import { Terminal } from '@xterm/xterm';
    ```

    Both an ESM module (`lib/xterm.mjs`) and a CommonJS module (`lib/xterm.js`) are shipped in the package. Most bundlers will automatically pick the correct format.
  </Tab>
  <Tab title="CommonJS">
    For Node.js scripts or older toolchains that use `require`:

    ```javascript
    const { Terminal } = require('@xterm/xterm');
    ```
  </Tab>
</Tabs>

## Including the stylesheet

<Note>
  xterm.js requires its CSS file to render correctly. Without it, the terminal will not display properly — characters may overlap and selection highlighting will be missing.

  **With a bundler**, import the CSS in your JavaScript entry point:

  ```typescript
  import '@xterm/xterm/css/xterm.css';
  ```

  **With a plain HTML file**, add a `<link>` tag in `<head>`:

  ```html
  <link rel="stylesheet" href="node_modules/@xterm/xterm/css/xterm.css" />
  ```
</Note>

## Standalone script tag

If you are not using a bundler, load the pre-built UMD bundle and stylesheet directly. This exposes `Terminal` as a global:

```html
<!doctype html>
<html>
  <head>
    <link rel="stylesheet" href="node_modules/@xterm/xterm/css/xterm.css" />
    <script src="node_modules/@xterm/xterm/lib/xterm.js"></script>
  </head>
  <body>
    <div id="terminal"></div>
    <script>
      const term = new Terminal();
      term.open(document.getElementById('terminal'));
      term.write('Hello from \x1B[1;3;31mxterm.js\x1B[0m $ ');
    </script>
  </body>
</html>
```

The UMD bundle is at `node_modules/@xterm/xterm/lib/xterm.js`. You can also serve it from a CDN that mirrors npm packages.

## Headless Node.js package

For server-side use without a DOM — such as tracking terminal state and restoring sessions — install the headless package instead:

<CodeGroup>

```bash npm
npm install @xterm/headless
```

```bash yarn
yarn add @xterm/headless
```

```bash pnpm
pnpm add @xterm/headless
```

</CodeGroup>

```typescript
import { Terminal } from '@xterm/headless';

const term = new Terminal({ cols: 80, rows: 24 });
term.write('output from a process\r\n');
```

`@xterm/headless` is a stripped-down build of xterm.js with no browser dependencies. A common pattern is to pair it with [`@xterm/addon-serialize`](/addons/serialize) to snapshot the terminal buffer so it can be restored when a client reconnects.

See the [Headless guide](/guides/headless) for a complete example.

## Beta builds

Beta releases are continuously published from the `master` branch. The principal consumer (VS Code) typically tracks the latest beta, so beta builds are generally stable — but they may contain breaking changes.

```bash
npm install @xterm/xterm@beta
```

Use beta builds to test upcoming features or verify bug fixes before a stable release.

## TypeScript support

Type declarations are bundled at `typings/xterm.d.ts` and referenced in the `package.json` `types` field. TypeScript resolves them automatically — no `@types/` package needed.

```typescript
import { Terminal, ITerminalOptions } from '@xterm/xterm';

const options: ITerminalOptions = {
  cursorBlink: true,
  fontSize: 14,
  fontFamily: '"Cascadia Code", monospace',
};

const term = new Terminal(options);
```

Some APIs are marked as **experimental** in the type declarations. These require `allowProposedApi: true` when constructing the `Terminal`, and may change between minor versions.

## Browser support

xterm.js targets the latest versions of modern evergreen browsers:

| Browser | Supported |
|---------|-----------|
| Chrome  | Latest    |
| Edge    | Latest    |
| Firefox | Latest    |
| Safari  | Latest    |

xterm.js also works in [Electron](https://electronjs.org/) apps and may work in older browser versions, but these are not officially supported.
